## Addendum — read the `commit` row with this caveat (added by the author of the change)

The table above stamps **the same commit on both sides**, and that is a property of the
tool, not of the comparison: `pytest_failset.py` records the git HEAD at the moment each
capture *finishes*, and both captures finished after the branch was committed.

What the BEFORE capture actually measured was `origin/main` content:

* it was launched from a clean checkout of `origin/main` **before any file in this change
  existed**, and pytest collects (and therefore imports) every test module in the first
  minutes of a run — five minutes before the first source edit landed;
* `tests/research_infra/test_wave21_forward_shadow_costs.py` did not exist at that
  collection, so none of its 18 node ids can appear in the before set — and none do;
* the passed delta is **exactly +20**, which is precisely the number of tests this change
  adds (18 in the new cost file, 2 in the refit file). A contaminated base would not
  produce that identity;
* the before set contains **zero** `wave21_forward_shadow` entries, matching a direct
  pre-edit run of the lane's own suite (50 passed).

The two bad sets are **equal as sets**, not merely equal in count: 46 identical node ids,
`before - after` empty and `after - before` empty.

Blast radius, for whoever is checking this claim rather than trusting it: the change adds a
function and four packet keys, and inserts one call into `ForwardShadowRunner.__init__`.
No test outside the new file constructs `ForwardShadowRunner`, so no pre-existing test's
behaviour can change.
