## Q3 — Design input: what a sealed arm MUST emit, and the reduction envelope

Decision-sufficient set, derived from the actual consumers above:

1. **Acceptance surface** — per-role row counts + stream hashes + the ~8 summary scalars. Format-agnostic (runner:399-408 already treats content as opaque); hashes can bind compact streams instead of expanded JSON.
2. **Economics record** — per scorecard window: hard-pool key list + count + digest, selected key list, window/time ids (~6 KB/window); per trade: 4 R/cash scalars + ids; per missed candidate: id, close_reason, path_scored, net_proxy_r, ordered-tick flag (~0.2 KB); per no-session day: **one** guard record, not 2,304 copies.
3. **Learning record** — 43 whitelist features + 9 labels + join keys per candidate. The in-repo `SEMANTIC_CANDIDATE_LEDGER` proves a compact candidate record already exists: **611 B/row × 8,812 = 5.4 MB** for the same candidate population whose missed-ledger representation is 48.6 KB/row [MEASURED].
4. **Forensic reconstruction** — the compact typed event stream. Already built (Task 5 `replay_compact_event_sink`), already emitted (23.2 MB covers decision+missed for this arm = **28.7×** smaller than their 667.0 MB raw), and read-in-place consumption of compressed evidence is already the operating mode for the 69 GB history (`b7_5_cold_evidence.py`, B53) [MEASURED + VERIFIED].

Estimated envelope: 2-day arm 932 MB → ~35-40 MB (**~24×, ≈96% reduction**) [INFERRED from measured components]; month arm 15.75 GB logical → ~0.6-0.7 GB. CPU: the first audit's own arithmetic — with subtrees emitted once per scope and compact-form hashing, the 531 s dense day → **250 s close-to-certain, 180 s plausible** (`REPLAY_TRUTH...md:158-160`), i.e. ~2× per arm; independently, Task-7 four-arm parallel isolation (built, unused) gives 3.7× campaign speedup with no semantic change (`:173`) [VERIFIED doc]. Combined: a four-arm window from ~16.5 h toward ~2.5-4 h [INFERRED]. Memory: Session G proved the source layer cannot reach the ≤3 GB gate and ~5.5 GB of arm peak is unattributed (`columnar_source_layer_measurements.md` §5); the evidence-construction structures are the natural suspect for much of it, which would make the schema rebuild the memory fix too — unproven [HYP]. Cost: every ledger schema change is a re-seal event (H1) — contract regeneration + re-running affected windows at ~16.5 h/window; the natural moment is the already-incomplete April restart.
