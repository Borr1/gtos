## Appendix — Reviewer sanity checks performed

1. **Report methodology verified continuous with ADR 002/003:** recomputed pooled winner p90 (1.096)
   matches session-brief n=121 reference (1.060) within 0.036 ATR; loser p10 (0.868) matches
   reference (0.870) within 0.002 ATR. Report §2. This rules out a methodology-drift artefact.
2. **Deviation threshold pre-registration check:** Report §1 states the ≥0.2 ATR threshold
   BEFORE the per-symbol numbers in §3. Threshold chosen on the principled basis "0.2 ATR = 40% of
   the current 0.5 ATR floor, which would materially shift the SL decision." Not post-hoc.
3. **Bonferroni correction:** the task brief specified α/5 for a 5-symbol multi-comparison. The
   report applies α/10 for 10 pairwise comparisons — the stricter choice. All 10 raw p-values are
   ≥ 0.044, so even the un-corrected comparisons fail α=0.05; the conclusion is robust to the
   correction choice.
4. **Live code read:** `config/agent_config.yaml` L50 (`ob_retest_sl_min_buffer_atr: 0.5`) ties
   directly to the Apr 16 sweep motivation. No per-symbol override fields exist in current config —
   shipping per-symbol buffers would have required new config keys and a permissions.py change;
   report's KILL verdict means none of that is needed.
5. **ADR 004 cross-check:** B6's finding that every symbol's loser p10 is ≥0.857 ATR is consistent
   with ADR 004's tight-cohort data (buffer <0.5 ATR → WR 44.87%, 100% swept). The two studies agree:
   0.5 ATR is the correct unified floor; sweeping below it loses; no symbol deviates enough to justify
   an exception.

**Summary for CEO:** B6 produces a clean NULL — no per-symbol tuning is justified by the historical
MAE evidence, and the unified 0.5 ATR floor (validated by ADR 004 against the Apr 16 sweep loss)
stands unchanged. Pre-challenge safe because the verdict requires zero live code change. Optional
follow-up: a shadow monitor to watch for future drift, non-urgent, can ship post-challenge.
