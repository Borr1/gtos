## 1. Pre-registration (recorded BEFORE looking at any scheme-level numbers)

Per CLAUDE.md "hypothesis BEFORE data" rule. Methodology was fixed before the `q62_replay.py` script was executed on the multi-scheme universe.

### 1.1 Hypothesis

> The current live partial-close scheme Variant C (33% @ +1.0R, 67% runner to +1.5R TP1) was just DEFER'd on the B2 replay (Wilcoxon p = 0.363, cum Δ = +5.76R, n=45, see `research/variant_c/variant_c_replay_decision_2026-04-18.md`). Q-6.2 asks whether a different split ratio is meaningfully better than Variant C or the baseline full-TP exit.

**H0:** For every candidate partial-close scheme (C, D1, D2, D3), the per-trade delta vs baseline has median zero.
**H1:** At least one scheme has a non-zero median delta and its mean delta is positive with Bonferroni-corrected significance.

### 1.2 Schemes

| Scheme | Composition | Trigger | Rationale |
|---|---|---|---|
| **Baseline** | 100% @ actual exit (current multi-TP + trail) | n/a | Reference. Delta = 0 by construction. |
| **C** | 33% @ +1.0R, 67% runner (BE stop if reversed past entry) | mfe_r ≥ 1.0 | Live Variant C. Mirror of `src/components/partial_close_shadow_logger.py`. |
| **D1** | 50% @ +1.0R, 50% runner | mfe_r ≥ 1.0 | Heavier partial — more variance compression, less runner capture. |
| **D2** | 25% @ +1.0R, 25% @ +1.5R, 50% runner | mfe_r ≥ 1.5 | Stepped exit. Bank some at 1R, more at 1.5R, let 50% run. |
| **D3** | 33% @ +1.0R, 33% @ +1.5R, 34% runner | mfe_r ≥ 1.5 | Equal-thirds stepped exit. |

In all schemes the runner leg is BE-protected: if price reverses past entry after the last partial, the runner returns 0 R (not negative). `remaining_r` for the runner is derived from `r_path` (exact) when present, else from the `r_multiple` sign (approx: winners → runner = r_multiple; losers → runner = 0).

### 1.3 Primary metric

**Mean per-trade delta_R vs baseline (actual r_multiple).**

Computed **only on trades that triggered the scheme**. Trades whose MFE never reached a scheme's minimum R are not in that scheme's sample (they have no delta — scheme outcome == baseline).

### 1.4 Sample threshold

**n ≥ 30 per scheme.** Schemes with fewer than 30 triggered trades are flagged "underpowered" and excluded from ranking.

### 1.5 Secondary metrics

- Wilcoxon signed-rank p (two-sided, zero-method=wilcox) on delta series
- Bootstrap 95% CI on mean (10k resamples, seed 20260418)
- Max 20-trade rolling-sum drawdown on delta series
- Win/loss split on delta_R sign

### 1.6 Multiple-comparison correction

**Bonferroni α = 0.05 / 4 = 0.0125** for 4 schemes each compared to baseline. A scheme only counts as "significant vs baseline" if Wilcoxon two-sided p < 0.0125.

### 1.7 Decision rule (pre-registered)

- **PROMOTE scheme X** if: X passes Bonferroni (p < 0.0125) AND X has positive mean delta AND X is top-ranked by mean delta.
- **NULL** if: top-ranked scheme has mean delta ≤ 0 (no partial scheme improves expectancy).
- **DEFER** otherwise (positive direction but not significant).

Note: Passing Bonferroni in the WRONG direction (scheme significantly WORSE than baseline) is a promotion blocker — reported as "significantly worse" with guidance to KILL further work on that variant.

## 2. Methodology

### 2.1 Universe construction

`load_universe()` in `q62_replay.py` unions three batch sources dedup'd by `trade_id`:

| Source | Unique trades | Has `r_path` | Used for |
|---|---|---|---|
| `batch_api/*_results.json` (40 files) | 318 (dedup'd) | 0 | Scalar mfe_r / r_multiple |
| `analysis/unified_trades_v2_20260331.json` | 111 (subset of 318) | 0 | Rich metadata (overrides batch_api) |
| `analysis/phase1_all_trades_merged.json` | 18 | 18 | Bar-by-bar `r_path` (overrides) |

**Total union: 336 trade records.**
**Valid subset (mfe_r + r_multiple + direction ∈ {LONG, SHORT}): 251 trades.**

### 2.2 Scheme computation

`scheme_r(trade, scheme_name)` — for each scheme:
1. If `mfe_r < min_trigger_R`: return None (scheme didn't fire).
2. Sum fixed partials: Σ fraction × R_level for each (fraction, R_level) leg where R_level ≤ mfe_r.
3. Compute runner_R:
   - **Exact (r_path present):** locate the bar where price first reached the highest fixed partial (e.g., +1.5R for D2/D3). Walk bars AFTER that bar; if `r_at_low ≤ 0` or `r_at_close ≤ 0` on any later bar, runner = 0 (BE stop). Else runner = r_multiple.
   - **Approx (no r_path):** winners (r_multiple > 0) → runner = r_multiple; losers (r_multiple ≤ 0) → runner = 0 (BE stop; price must have crossed entry between the partial fill and the SL).
4. Add runner_fraction × runner_R.
5. Return blended R.

### 2.3 Baseline definition

Baseline delta = 0 per trade by construction. The reference is `actual_r_multiple` as recorded in the batch corpus, which reflects the **current system's actual exit rules** (multi-TP + trailing stop + session timeout — not a clean 100% @ +1.5R TP). This is the same framing as the Variant C B2 replay and means "delta > 0" reads as "scheme beats current exit", not "scheme beats a naïve TP1 holder".

### 2.4 Sanity check — Variant C vs prior replay

I re-ran Variant C on the exact prior 129-trade subset (unified + phase1_merged only, the B2 universe). **Result: n=45, mean Δ=+0.12794, cum Δ=+5.7571 — byte-identical to `research/variant_c/variant_c_replay_decision_2026-04-18.md` (n=45, +0.1279, +5.7571).** Methodology is confirmed equivalent; the difference between this study and B2 is purely the broader universe (251 vs 129).

### 2.5 Data quality notes

- 7 of 251 trades have `r_multiple > mfe_r` by a small margin (max 0.66 R gap on `bt_2025-09-26_ny_001`). Likely bar-close sampling artefact where MFE was recorded at a coarser granularity than fill. All 7 are wins with mfe_r < 1.0, so they don't trigger any scheme and don't affect results.
- 14 of 251 trades touched +1.0R MFE and still closed at SL (mfe_r ≥ 1.0 ∧ r_multiple ≤ 0). These are the "runner reversed past entry to SL" cohort Variant C / D1 rescue.
- 7 of 251 touched +1.5R MFE and closed at SL. Subset for D2/D3 rescue effect.

### 2.6 What this replay does NOT model

Same caveats as the B2 decision doc:
1. No spread or partial-close slippage (~0.05–0.15 R per partial leg on XAUUSD)
2. No live MT5 partial-close order mechanics (lot rounding, rejection handling)
3. `r_path` at M15 bar resolution; tick-level fills may diverge
4. Approx mode heuristic treats winner-reversal-then-recovery as monotone (minor overestimate)
5. Universe is XAUUSD-only (`unified_trades_v2` predates multi-instrument expansion; all 3 sources have no `symbol` field)
6. 2024-04 → 2026-03 regime includes strong XAUUSD bull (~$2250 → $5000); runner capture is regime-dependent
7. Baseline ≠ 100%@TP1; it's the live multi-TP + trail exit as recorded

### 3.2 Apples-to-apples — common-trigger subset (mfe_r ≥ 1.5, n=71)

Because C/D1 trigger on +1.0R and D2/D3 trigger on +1.5R, a fair head-to-head requires restricting to trades that trigger all four schemes (mfe_r ≥ 1.5).

Subset: n=71, mean actual r_multiple = +1.473 (these are mostly strong winners).

| Scheme | n | mean Δ R | cum Δ R | Wilcoxon p (2s) |
|---|---|---|---|---|
| C  | 71 | −0.0983 | −6.98 | **0.0058** ← passes Bonferroni, WRONG direction |
| D1 | 71 | −0.1933 | −13.73 | **0.0057** ← passes Bonferroni, WRONG direction |
| D2 | 71 | −0.0683 | −4.85  | 0.1570 |
| D3 | 71 | −0.1177 | −8.36  | 0.1536 |

**Critical finding:** On the subset where all schemes trigger, C and D1 are **significantly WORSE** than the baseline at Bonferroni-corrected α. The apples-to-apples view confirms that partial-close schemes GIVE UP positive expectancy on the high-MFE cohort.

### 3.3 Mechanism decomposition (Variant C, universe n=102)

Split the 102 +1R-triggered trades by whether they reversed past entry to SL:

| Cohort | n | mean actual R | Variant C runner | Variant C blended R | mean Δ R |
|---|---|---|---|---|---|
| Reversed to SL (mfe≥1R, r_mult≤0) | 14 | −0.936 | 0 (BE stop) | 0.33 | **+1.266** |
| Did NOT reverse (winners + small losers) | 88 | ? | r_mult | 0.33 + 0.67·r_mult | −0.139 |

The +0.054 R/trade headline for Variant C is entirely the 14 reversed-loser rescues (+17.7 R cumulatively) minus the runner give-up on 88 non-reversing trades (−12.3 R). Pure variance compression, no true expectancy lift.

### 3.4 Why D2/D3 did worse than C/D1

D2/D3 trigger at +1.5R — the population with **already-high realised R**. On this cohort:
- Baseline (actual) mean R: +1.473
- D2 (0.25@1R, 0.25@1.5R, 0.50 runner): mean partial contribution = 0.625 R, then 0.50 × (avg runner = 1.47 if held) = extra 0.735 R → total ~1.36 R = −0.11 below baseline.
- The more partials you book early, the less you benefit from the large upside tail of +2R to +4R winners.

### 3.5 Variant C expansion dilution (vs B2's n=45 result)

The B2 replay on the 129-trade subset gave mean Δ = +0.1279; this broader 251-trade universe gives +0.0536. The dilution is because the broader batch_api universe contains more shallow-winning trades (r_mult between 0 and 1.0) that do NOT trigger +1R, and among those that DO trigger, a higher proportion are monotone winners that "pay" more in foregone runner than the reversed-loser rescues can compensate for. Both sample sizes now report positive-but-not-significant headlines.

### 4.2 Verdict: **DEFER**

No scheme clears the pre-registered Bonferroni promotion threshold (α=0.0125) in the positive direction. The nominal ranking (C > D1 > D2 > D3) matches the prior B2 conclusion that Variant C is the strongest partial-close candidate, but:

1. **C's advantage is not statistically significant** even before correction (p=0.957 two-sided). The "+0.054 R/trade" mean is inside a 95% bootstrap CI of [−0.054, +0.168] — the signal is consistent with noise.
2. **D1 is nearly identical to C** in nominal mean (+0.015) and rank — no split-ratio sweet spot emerges between 33% and 50%.
3. **D2/D3 (multi-level schemes) are strictly worse than C/D1** on the +1.5R-trigger cohort, consistent with the bank-early-forgo-runner mechanism.
4. **On the common-trigger subset, C and D1 are significantly WORSE than baseline at Bonferroni α.** This is the strongest evidence in the study — partial-close schemes hurt the system on the high-MFE subset.

### 4.3 Explicit mechanism (why no scheme wins)

Partial closing at +1.0R on gold has two opposing effects:
- **Positive:** Saves ~33–50% of risk on trades that touch +1R and reverse to SL. In this corpus, 14 of 102 +1R-triggered trades (13.7%) fit this pattern. Variant C saves +1.266 R per rescue, cumulatively +17.7 R.
- **Negative:** Forfeits 33–50% of runner upside on trades that touch +1R and continue. 88 of 102 (86.3%) are in this cohort. Variant C forfeits −0.139 R per trade, cumulatively −12.3 R.

**Net:** +5.5 R / 102 trades = +0.054 R/trade, well within noise.

The XAUUSD trade distribution during 2024-04 → 2026-03 — a structurally trending bull regime with ξ=0.35 fat right tail — rewards runner holding more than it punishes runner reversal. Partial-close schemes would be more attractive in a chop/reversion regime where +1R touches frequently precede full-SL outcomes. That regime has not been sampled adequately in this universe.

### 4.4 Recommendation to CEO

1. **Do NOT queue Variant D for shadow-logging.** None of D1/D2/D3 is better than the already-shadow-logged Variant C on the data, and the apples-to-apples analysis says C and D1 are significantly worse than baseline on high-MFE trades.
2. **Maintain the existing Variant C live shadow logger.** No change to live system. Consistent with the B2 DEFER recommendation.
3. **Re-evaluate post-challenge (≥ 6 months).** When ≥ 30 LIVE +1R-triggered events accumulate in `shadow_logs/partial_close_shadow_log.jsonl`, re-run this analysis with live data — out-of-sample evidence is the only way to overturn the in-sample null.
4. **If/when regime changes** (gold chop or mean-reversion dominant), the reversed-loser rescue rate may increase and partial schemes may turn profitable. A regime-conditional activation is plausible research but out of scope for this question.

## 5. Gaps and limitations

Same list as Variant C B2 decision, reproduced briefly:

1. **In-sample XAUUSD-only.** No out-of-sample or cross-instrument validation.
2. **No spread / slippage modelled.** A 0.05-0.15 R partial-leg cost would pull Variant C's +0.054 R headline below zero.
3. **`r_path` coverage is 9 of 102 (Variant C triggers) / 7 of 71 (D2/D3 triggers).** 90%+ of rows use approx heuristic; directly-measurable reversal-past-entry is a small minority.
4. **Baseline ≠ pure-TP1 hold.** The batch corpus was run with multi-TP + trail, so "scheme vs baseline" is "scheme vs current live exit", not "scheme vs naïve 100% @ TP1".
5. **Bull regime.** 2024-04 → 2026-03 was a strong gold uptrend; runner expectancy is above historical norms.
6. **No per-instrument analysis possible.** All 251 trades are XAUUSD (no `symbol` field; both universe files pre-date multi-instrument expansion).
7. **Partial-close live mechanics untested.** `src/components/execution.py` has no partial-close code path. Shipping any scheme would require new code + new tests + a restart cycle.
