## 3. Cross-instrument gate's hardcoded fallback — provenance

Verified the `_FALLBACK_CORRELATION_TABLE` (lines 86–161 of `cross_instrument_correlation_gate.py` on `feat/cross-instrument-correlation-gate`) round-trips byte-equivalently to the stale JSON for **all 15 spot-checked pairs** (XAU↔AUD, XAU↔GBP, XAU↔US30, XAU↔USDJPY, XAU↔XAG, XAU↔EUR, AUD↔NZD, US30↔US500, EUR↔GBPJPY, USDJPY↔GBPJPY, EUR↔GBP, EUR↔USDCAD, AUD↔USDCAD, GBP↔USDCAD, NZD↔USDCAD — all `MATCH` after rounding to 3 decimals). The gate operator is consequently equally stale whether the JSON is loaded or the fallback fires.

**Implication:** The gate's "JSON-or-fallback" indirection is empty optionality at present — both branches resolve to the same Apr-4 numbers. To get fresh data into the gate either:

a) **Overwrite the JSON in-place** (smallest diff, but the symbol set drops from 24 candidates back to the 13 the gate currently keys on; `cross_instrument_correlation_gate.py::_CORRELATION_TABLE` keying logic doesn't enumerate symbols at module-load and would seamlessly absorb a 13-pair update of the same shape).

b) **Replace JSON with the 24×24 file** and update `_FALLBACK_CORRELATION_TABLE` in the same PR. This brings AUDJPY, BTCUSD, CHFJPY, ETHUSD, EURGBP, GER40, JP225, NAS100, SPX500, UK100, UKOIL_cash, USDCHF into the gate's purview. None are LIVE today, but the structural-screen ranking suggests several (EURGBP, NAS100, USDCHF) as imminent expansion candidates and shipping the matrix in 24×24 form removes a future re-roll.

c) **Drop the structural-screen CSV directly** (by adding a CSV reader to `_load_correlation_table()`). Highest source-of-truth fidelity but largest code diff; unnecessary if (b) is acceptable.

**Recommendation: option (b)** — overwrite the JSON with a 24×24 fresh matrix, regenerate the fallback dict literal in the gate file from the same data, ship the diff in the cross-instrument-gate PR before Monday.

### 4.1 `US500` symbol-naming bug — Q-blocker for any US-indices pair trading

`portfolio_risk.py:41` literal:
```python
"US_INDICES": {
    "instruments": ["US30_cash", "US500"],
    "max_combined_risk_pct": 1.5,
},
```

Mirrored in `config/agent_config.yaml:268-270`:
```yaml
US_INDICES:
  instruments: [US30_cash, US500]
```

But the canonical broker-symbol everywhere else in the codebase is `US500_cash` (see `src/prompts/primary_analyzer_prompt.py:186`: `_POINT_INSTRUMENTS = ("NAS100", "US30_cash", "US500_cash")`; and the correlation matrix keys `US500_cash`). MT5 returns the broker symbol verbatim, and the canonical screening dataset uses `US500_cash`.

`portfolio_risk.check_correlation_risk()` matches by literal-string membership in the group's `instruments` list (line 93). If a position is open on `US500_cash` and a candidate fires for `US30_cash`, the loop iterates only `US_INDICES` for `US30_cash` membership — passes — then checks each open position's `pos_symbol in instruments` — `US500_cash` is **not** in `["US30_cash", "US500"]`, so the group never fires. Group is dead. The `instruments[…, "US500"]` line is unreachable for any real-world trade.

**Severity:** functional, but US500 has never been listed in the live `instruments:` block of `agent_config.yaml`, so the bug is dormant — there is no live US500_cash position to trigger it. If the CEO promotes US500_cash to live (or NAS100 — which would warrant a separate index-pair entry), this group would silently fail. Reverse impact: even today, the cross-instrument gate's fresh-matrix lookup would catch US30_cash↔US500_cash @ +0.937 via the 0.4 threshold path, so the US_INDICES group's nominal `max_combined_risk_pct=1.5` is shadowed correctly by the layered gate. Belt-and-suspenders: fix the typo.

**Action:** change `"US500"` → `"US500_cash"` in both `portfolio_risk.py:41` and `agent_config.yaml:269`. Pure-additive, no behavior change for current live fleet.
