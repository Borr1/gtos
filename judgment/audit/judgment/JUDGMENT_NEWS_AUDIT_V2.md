## Disagreements that change the plan

1. **Against adding more seats or more frequent LLM wakes as the root fix.** The state transport can lose, stale-bind and overextend a perfectly reasoned answer. Repair it first. Two live seats remain enough; the writer must process event state without waiting for either seat to speak.
2. **Against "slate rebound" as the full explanation.** Sender rebinding and consumer mismatch are different errors. Event hazards persist across slate changes; candidate and position actions must remain bound to the exact object. A current fingerprint must never be copied onto old reasoning merely to force acceptance.
3. **Against "underwater near news means broken."** V3 C2 says that; C4 requires a much stronger conjunction. Red P&L plus a scheduled release is not a mechanical failure. Preserve the existing green-ticket leave at T−45. Only a present, ticket-specific defect or explicit owner instruction permits manage.
4. **Against a blanket one-hour correlation veto after the fill.** It misses the existing risk and can suppress later independent entries. Bind correlation to the compared book version and exact future fire; recompute after fills/closes. Counting three same-direction names is not itself a measured portfolio-risk rule.
5. **Against "every exit outside orig/TP/time is BREACH" in V3.** A valid, authorized broken-container close is not automatically a policy breach. Store exit cause, authorization and compliance separately. A trade can be compliant and lose, or be an unauthorized profitable close.
6. **Against treating one MFE giveback as a false loser.** Gold-long 180322126 giving back2.47R is not proof that take-at2R is the right policy when that same take cut gold-short's6R destination. Compare predefined policies on all eligible trades, after costs and executable first-touch order.
7. **Against quote-direction anecdotes as edge.** More excursion, bigger ranges or correct macro direction is not positive expectancy after entry, spread, stop and opportunity cost. The owner is correct to demand improvement; the supplied evidence does not justify guaranteed consistent payouts.
8. **Against increasing event size because the −45 amplifier is wired.** Wave2 proves an assignment/meta path; multiplier1.0 is still neutral. Range expansion is not a direction or risk-adjusted profit estimate.

## News redesign

The companion `NEWS_PROTOCOL_V2.md` is the exact staged protocol. Retain current live timing and size until its law-changing parts receive the prescribed deployment ceremony. The first repair is transport and observability, with no new broad veto. A scheduled event already has a known time: precompute its start/end and affected symbol set. The writer consumes that state locally at the send boundary. WATCH owns facts and revisions; CHAIR owns scoped judgment and interpretation; neither is a required network hop in a scheduled no-new-risk check.

At the T−15 boundary, reconcile each affected native pending against broker state and request cancellation through the writer; record broker response and any race fill. A fill that wins the race is a new open position governed by its original contract, not a candidate to retroactively flatten. Existing orig/TP positions continue their existing law. This pending behavior is a concrete implementation of the claimed event contract, but it changes actual live behavior and therefore is staged for the owner ceremony.

For unscheduled accepted-class events, WATCH supplies one stable event identity and source observation time. The receiving process validates and commits that event separately from any candidate slate. No repeated headline can reset its expiry. The deterministic writer re-evaluates only affected future orders and pending exposure; CHAIR investigates the context without waiting for a new slate to invent an event row. Non-policy headlines remain context annotations and shadow hypotheses, so news does not become an automatic universal HOLD.

Keep actual T−15..T+60 as the current strategy policy, distinguish it from FTMO's rules, and study less idle alternatives now using recorded/historical data. Candidate policies to compare include T+5/15/30/60 reopen and condition-based reopen after spread/quote/liquidity normalization, evaluated per event class and symbol. Use predeclared spread and slippage measures, original pending level/expiry, repeated-event dependence, and all missed winners plus avoided losers. Do not optimize on Sep4 alone. The elapsed minutes are candidate treatment arms, not recommendations or a new live rule.

The positive contribution of intelligence is an event-aware opportunity queue: each valid frozen candidate records why it is still useful after the event, expiry, entry level, cost limit and the condition for re-evaluation. On event expiry the writer immediately re-evaluates eligible existing strategy candidates; it never remints a spent ticket or converts a missed limit into a chasing market order. Longer macro context guides research and named candidate annotations; validated selection rules can graduate later through a versioned ship.

## Acceptance and limits

Engineering targets, to be measured rather than advertised as achieved: local event commit-to-admission visibility p99≤1s under peak captured load; ingest-receipt-to-validated event commit p99≤5s for already-supported event types; each broker action emits a received/applied/consumed/broker-result trail. External publication-to-receipt has its own measured distribution and cannot be guaranteed by an internal service target. Scheduled gates must work with both agents unreachable.

Test the actual NFP trace, an ordinary quiet hour, two simultaneous distinct events, duplicate/delayed headlines, event time correction, all-dark seats, writer restart under live contracts, queue burst, corrupt source, concurrent WATCH/CHAIR writes, stale snapshot, missing/failed acknowledgement, atomic write failure, and pending cancel/fill race. Positive tests matter: unaffected symbols still print; a new valid15m re-entry can print; an expired event cannot be renewed by a duplicate; valid existing runners retain orig/TP; short-lived correlation evidence cannot leak to an unrelated later fire.

Residual uncertainties: this lane did not access actual Grok Bot runtime routine definitions or the original Walter ingress receipts. SEATS_V3 describes intended seat configuration, not verified current configuration. The runtime snapshot does include decision journals, inbox archives, current canonical calendars, the seven exact source byte strings and launcher/watcher logs, analyzed below. No lane can infer a repeatable payout edge from passing these reliability tests.
